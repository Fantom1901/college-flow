# 🗺 User Flow — DutyMaster (Telegram WebApp)

Полная спецификация путей пользователя. 
**Философия проекта:** Автоматизация рутины и полная прозрачность. Система исключает "ручное" управление рейтингом для предотвращения кумовства.

---

## 🎭 1. Роль: SuperAdmin (Root)
*Уровень системного администрирования.*

1. **Инициация системы:** Вызов метода генерации уникального `InviteLink` для Куратора.
2. **Безопасность:** Ссылка является одноразовой и имеет ограниченный срок жизни.
3. **Мониторинг:** Доступ к эндпоинту `/system/health` для контроля состояния БД и сервера.

---

## 🏫 2. Роль: Куратор (Владелец группы)
*Единственное лицо с правом формирования состава и структуры.*

1. **Авторизация:** Переход по ссылке -> Валидация через Telegram `initData`.
2. **Создание группы:**
    * Ввод официального названия (напр. "ИСП-41").
    * Система создает уникальный `GroupID` и привязывает Куратора как владельца.
3. **Наполнение группы (Smart List):**
    * Ввод ФИО первого студента -> Клик по иконке [✔].
    * **Логика:** Система сохраняет студента в локальный стейт, очищает поле ввода и анимированно выкатывает новую карточку.
    * Повторение до завершения списка. Доступна возможность удаления ошибочно введенных карточек до момента отправки.
4. **Массовая генерация:** Нажатие на Floating Action Button **"Invite"**.
5. **Дистрибуция:** Бэкэнд создает пачку UUID-инвайтов. Куратор видит список "ФИО — Ссылка" и кнопку "Скопировать всё для чата".

---

## 👤 3. Роль: Студент (Участник очереди)
*Пользователь с правами на личные уведомления и P2P обмен.*

1. **Регистрация (Onboarding):**
    * Переход по персональной ссылке.
    * Система автоматически сопоставляет `tg_id` юзера с `student_id` в базе.
2. **Главный экран (Dashboard):**
    * **Виджет "Дежурство":** Кто дежурит сегодня, кто следующий в очереди.
    * **Виджет "Посещаемость":** Счетчик собственных опозданий и пропусков.
3. **Инструменты оповещения (Quick Actions):**
    * **Кнопка "Я опоздаю":** Выбор времени из пресетов (10/20/30 мин) + поле "Причина". Бот мгновенно уведомляет Лидера.
    * **Кнопка "Меня не будет":** Форма ввода причины. Данные улетают в рапорт Лидеру.
4. **Обмен дежурствами (P2P Exchange):**
    * Выбор даты/человека для обмена -> Отправка запроса.
    * Получение подтверждения через Telegram-бота от второго участника.
    * **Логика:** Веса студентов не меняются, меняются только их ID в расписании на конкретные даты.

---

## 🎖 4. Роль: Лидер (Староста)
*Операционный менеджер группы с жестко ограниченными правами.*

1. **Управление дежурством (The Grid):**
    * **Confirm:** Кнопка подтверждения факта уборки. 
        * *Backend Logic:* При нажатии система берет текущий `base_weight` студента и прибавляет к нему константу (напр. +1). **Лидер не видит и не может изменить это число.**
    * **Skip:** Если студент болен, Лидер может пропустить его. Очередь переходит к следующему, вес "пропущенного" не меняется.
2. **Контроль посещаемости (Daily Report):**
    * Список группы с фильтром по статусам (Опаздывают / Отсутствуют).
    * Ручная отметка тех, кто не пришел и не предупредил.
    * Кнопка **"Отправить рапорт"** — данные фиксируются в истории и становятся доступны Куратору.
3. **🚫 Система Анти-Кумовства:**
    * Интерфейс Лидера **не содержит** полей ввода для рейтинга/веса.
    * Лидер не может удалить студента из группы (только Куратор).
    * Лидер не может вручную назначить дежурным "друга" — алгоритм всегда выбирает человека с наименьшим весом автоматически.

---

## 🎨 UI/UX Гайдлайн для команды

* **Стиль:** Использовать Blur-эффекты и скругления 12-16px (iOS/Telegram Style).
* **Цвета:** Использование `tg.themeParams` для поддержки темной и светлой тем.
* **Доступность:** Поля весов в интерфейсе Лидера должны быть визуально "погашены" (opacity 0.6) или оформлены как текстовые метки без возможности взаимодействия.
